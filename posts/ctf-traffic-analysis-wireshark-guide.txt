b:T15bb9,<h2 id="一-流量分析概述">一、流量分析概述</h2>
<p>流量分析（Traffic Analysis）是CTF中取证类题目的重要分支，主要通过分析网络数据包捕获文件（PCAP）来提取关键信息、还原攻击过程、挖掘隐藏数据。流量分析考验选手的网络协议知识、工具使用能力和逻辑推理能力。</p>
<p><strong>核心工具：Wireshark</strong> —— 业界最强大的图形化网络协议分析器，提供直观的界面和丰富的功能。</p>
<hr>

<h2 id="三-分析方法论">三、分析方法论</h2>
<h3 id="3-1-常规分析流程">3.1 常规分析流程</h3>
<pre><code>1. 打开PCAP文件 → 2. 协议统计分析 → 3. 关键会话筛选 → 4. 数据提取 → 5. 深度分析 → 6. Flag验证
</code></pre>
<h3 id="3-2-快速定位策略">3.2 快速定位策略</h3>
<p><strong>第一步：获取文件基本信息</strong></p>
<ul>
<li><code>File → Properties</code>：查看文件基本信息（捕获时间、数据包数量、文件大小等）</li>
<li><code>Statistics → Summary</code>：详细统计信息</li>
</ul>
<p><strong>第二步：识别关键协议</strong></p>
<ul>
<li><code>Statistics → Protocol Hierarchy</code>：协议层次统计，快速识别主要协议</li>
<li>观察数据包列表中的Protocol列</li>
</ul>
<p><strong>第三步：追踪特定数据流</strong></p>
<ul>
<li>在过滤器栏输入过滤条件</li>
<li>右键点击数据包 → <code>Follow</code> 追踪流</li>
<li>使用 <code>Statistics → Endpoints</code> 或 <code>Conversations</code> 查看通信端点</li>
</ul>
<h3 id="3-3-ctf-通用分析思路速查">3.3 CTF 通用分析思路速查</h3>
<p>拿到 PCAP 后，可按以下思路快速定位 flag：</p>
<ul>
<li>分组字节流直接搜索 <code>flag</code>、<code>flag{</code>、<code>f</code>、<code>fl</code> 等关键词（注意编码与干扰字符）。</li>
<li>包长度、响应时间、包间隔可能隐藏信息（时间通道）。</li>
<li>大量 GET/POST 参数可能是 SQL 盲注，可尝试回放重放。</li>
<li>TCP 流中可能隐藏编码信息；隐藏压缩包直接搜索 <code>504B0304</code>（PK 头），优先用 <code>File → Export Objects</code> 导出。</li>
<li>数据包 Info 字段中可能隐藏 base64 字符串。</li>
<li>一般 TCP 无信息、无密钥的 TLS 流量可先跳过。</li>
<li>ICMP 流量重点看 data 块长度与时间。</li>
<li>菜刀等 WebShell 流量可能 gzip 压缩，直接搜 <code>flag</code> 搜不到，需先解压。</li>
<li>不可打印字符可能是控制字符，对照 ASCII 表逐字节分析。</li>
</ul>

<h2 id="四-显示过滤器详解">四、显示过滤器详解</h2>
<h3 id="4-1-基础语法">4.1 基础语法</h3>
<p>在Wireshark过滤器栏中输入过滤表达式，按回车或点击Apply按钮应用。</p>
<p><strong>协议过滤：</strong></p>
<pre><code>http          # 显示所有HTTP协议数据包
tcp           # 显示所有TCP协议数据包
dns           # 显示所有DNS协议数据包
icmp          # 显示所有ICMP协议数据包
smb           # 显示所有SMB协议数据包
</code></pre>
<p><strong>字段过滤：</strong></p>
<pre><code>ip.src == 192.168.1.1    # 源IP地址
ip.dst == 192.168.1.1    # 目标IP地址
tcp.port == 80            # TCP端口号
udp.port == 53            # UDP端口号
http.request.method == "GET"  # HTTP方法
</code></pre>
<p><strong>逻辑运算符：</strong></p>
<pre><code>&#x26;&#x26;  # 与（AND）
||  # 或（OR）
!   # 非（NOT）
</code></pre>
<p><strong>比较运算符：</strong></p>
<pre><code>==  # 等于
!=  # 不等于
>   # 大于
&#x3C;   # 小于
contains  # 包含子字符串
matches   # 正则表达式匹配
</code></pre>

<h2 id="五-常见协议分析技巧-wireshark操作">五、常见协议分析技巧（Wireshark操作）</h2>
<h3 id="5-1-http协议分析">5.1 HTTP协议分析</h3>
<p><strong>基本操作：</strong></p>
<ol>
<li>
<p><strong>过滤HTTP流量</strong></p>
<ul>
<li>在过滤器栏输入 <code>http</code>，回车</li>
</ul>
</li>
<li>
<p><strong>查看HTTP请求详情</strong></p>
<ul>
<li>选中一个HTTP数据包</li>
<li>在数据包详情面板展开 <code>Hypertext Transfer Protocol</code></li>
<li>查看请求行、头部字段、请求体</li>
</ul>
</li>
<li>
<p><strong>提取HTTP请求参数</strong></p>
<ul>
<li>展开 <code>http.request.uri.query</code> 查看GET参数</li>
<li>展开 <code>http.file_data</code> 查看POST数据</li>
</ul>
</li>
<li>
<p><strong>查看HTTP响应</strong></p>
<ul>
<li>找到对应的响应数据包（通常在请求包之后）</li>
<li>展开 <code>http.response</code> 查看状态码</li>
<li>展开 <code>http.file_data</code> 查看响应体内容</li>
</ul>
</li>
<li>
<p><strong>追踪HTTP流</strong></p>
<ul>
<li>右键点击HTTP数据包</li>
<li>选择 <code>Follow → HTTP Stream</code></li>
<li>在弹出窗口中查看完整的请求-响应对话</li>
</ul>
</li>
</ol>
<p><strong>关键分析点：</strong></p>
<ul>
<li>请求参数中的敏感数据（如token、password）</li>
<li>响应中的隐藏信息（如注释、特殊编码）</li>
<li>Cookie中的会话信息</li>
<li>User-Agent、Referer等头部信息</li>
</ul>
<h3 id="5-2-https-tls协议分析">5.2 HTTPS/TLS协议分析</h3>
<p><strong>解密配置步骤：</strong></p>
<ol>
<li>
<p><strong>方法一：使用服务器私钥</strong></p>
<ul>
<li><code>Edit → Preferences → Protocols → TLS</code></li>
<li>点击 <code>RSA Keys List</code> 旁边的 <code>Edit</code> 按钮</li>
<li>添加密钥：IP地址、端口、协议、私钥文件路径</li>
</ul>
</li>
<li>
<p><strong>方法二：使用SSLKEYLOGFILE</strong></p>
<ul>
<li>在浏览器环境设置环境变量：<code>export SSLKEYLOGFILE=./sslkey.log</code></li>
<li>在Wireshark中：<code>Edit → Preferences → Protocols → TLS</code></li>
<li>在 <code>(Pre)-Master-Secret log filename</code> 中选择sslkey.log文件</li>
</ul>
</li>
<li>
<p><strong>方法三：使用浏览器插件导出密钥</strong></p>
<ul>
<li>使用Firefox的 <code>about:config</code> 设置 <code>security.ssl.debug</code> 为true</li>
<li>或使用Chrome的 <code>chrome://net-export/</code> 导出SSL密钥</li>
</ul>
</li>
</ol>
<p><strong>分析步骤：</strong></p>
<ol>
<li>配置解密后，HTTP流量会以明文形式显示</li>
<li>使用 <code>http</code> 过滤器查看解密后的内容</li>
<li>检查证书信息：展开 <code>Transport Layer Security → Certificate</code></li>
</ol>
<p><strong>常见漏洞：</strong></p>
<ul>
<li>SSL/TLS版本降级攻击（如POODLE）</li>
<li>证书验证绕过</li>
<li>弱加密套件（如RC4、DES）</li>
</ul>
<h3 id="5-3-dns协议分析">5.3 DNS协议分析</h3>
<p><strong>基本操作：</strong></p>
<ol>
<li>
<p><strong>过滤DNS流量</strong></p>
<ul>
<li>在过滤器栏输入 <code>dns</code>，回车</li>
</ul>
</li>
<li>
<p><strong>查看DNS查询</strong></p>

<h3 id="5-7-tcp协议深度分析">5.7 TCP协议深度分析</h3>
<p><strong>核心考点：三次握手、四次挥手、序列号分析、重传检测</strong></p>
<ol>
<li>
<p><strong>TCP三次握手分析</strong></p>
<ul>
<li>过滤 <code>tcp.flags.syn == 1</code> 查看SYN包</li>
<li>过滤 <code>tcp.flags.syn == 1 &#x26;&#x26; tcp.flags.ack == 1</code> 查看SYN+ACK包</li>
<li>过滤 <code>tcp.flags.ack == 1 &#x26;&#x26; tcp.seq == 1</code> 查看ACK包</li>
<li>分析序列号（<code>tcp.seq</code>）和确认号（<code>tcp.ack</code>）的关系</li>
</ul>
</li>
<li>
<p><strong>TCP四次挥手分析</strong></p>
<ul>
<li>过滤 <code>tcp.flags.fin == 1</code> 查看FIN包</li>
<li>观察FIN-WAIT、TIME-WAIT等状态</li>
<li>分析 <code>tcp.window_size</code> 的变化</li>
</ul>
</li>
<li>
<p><strong>序列号分析</strong></p>
<ul>
<li><code>tcp.seq</code>：发送方的序列号</li>
<li><code>tcp.ack</code>：期望接收的下一个字节序号</li>
<li><code>tcp.window_size</code>：接收窗口大小（流量控制）</li>
</ul>
</li>

<h3 id="5-9-ssh协议分析">5.9 SSH协议分析</h3>
<p><strong>核心考点：密钥交换、协议版本、认证过程</strong></p>
<ol>
<li>
<p><strong>基本过滤</strong></p>
<ul>
<li><code>ssh</code>：显示所有SSH流量</li>
<li><code>tcp.port == 22</code>：过滤SSH端口</li>
</ul>
</li>
<li>
<p><strong>SSH握手过程</strong></p>
<ul>
<li><strong>第一步：版本协商</strong>
<ul>
<li>客户端发送 <code>SSH-2.0-&#x3C;客户端版本></code></li>
<li>服务端回复 <code>SSH-2.0-&#x3C;服务端版本></code></li>
</ul>
</li>
<li><strong>第二步：密钥交换</strong>
<ul>
<li>交换算法协商（Kex）</li>
<li>公钥交换和签名验证</li>
</ul>
</li>
<li><strong>第三步：认证</strong>
<ul>
<li>支持密码认证、公钥认证等</li>
</ul>
</li>
</ul>
</li>
<li>
<p><strong>查看SSH版本信息</strong></p>
<ul>
<li>在数据包详情中展开 <code>Secure Shell → Protocol Version Exchange</code></li>
<li>查看客户端和服务端版本字符串</li>
</ul>
</li>
<li>
<p><strong>SSH协议字段</strong></p>
<ul>
<li><code>ssh.protocol_version</code>：协议版本</li>
<li><code>ssh.kex.algo</code>：密钥交换算法</li>
<li><code>ssh.host_key.algo</code>：主机密钥算法</li>
</ul>
</li>
<li>
<p><strong>SSH加密流量处理</strong></p>
<ul>
<li>SSH流量默认加密，无法直接查看内容</li>
<li>如果获取到私钥，可以尝试解密</li>
<li>关注握手阶段的明文信息</li>
</ul>
</li>
</ol>
<p><strong>CTF常见考点：</strong></p>
<ul>
<li>从版本字符串中提取隐藏信息</li>
<li>通过密钥交换过程分析加密强度</li>
<li>识别弱密钥或已知漏洞版本</li>
<li>SSH隧道中的隐蔽通信</li>
</ul>

<h3 id="5-16-dhcp协议分析">5.16 DHCP协议分析</h3>

<li><strong>DHCP ACK</strong>：服务器确认分配</li>

<li><code>dhcp.option.dhcp_message_type</code>：消息类型</li>
<li><code>dhcp.option.subnet_mask</code>：子网掩码</li>
<li><code>dhcp.option.router</code>：网关地址</li>
<li><code>dhcp.option.dns_server</code>：DNS服务器</li>
<li><code>dhcp.option.ip_address</code>：分配的IP地址</li>

<h3 id="6-3-rdp协议分析">6.3 RDP协议分析</h3>

<h3 id="6-4-流量隐蔽技术分析">6.4 流量隐蔽技术分析</h3>

</li>
<li>

</ul>

</ul>
</li>

</li>

<h3 id="6-5-蓝牙协议分析-obex">6.5 蓝牙协议分析（OBEX）</h3>
<p>蓝牙流量（如 <code>.btsnoop</code> 格式）在 CTF 中相对少见，出现时可用以下思路：</p>
<ul>
<li>分组字节流直接搜索 <code>flag</code> 等关键词。</li>
<li>使用协议分级中的 OBEX（Object Exchange，对象交换）作为过滤器，定位文件传输对象。</li>
<li>蓝牙配对 PIN 码：在数据包详情中搜索 <code>pin</code>（例如 <code>pin code:141854</code>），往往直接给出配对口令。</li>
</ul>
<h3 id="6-6-哥斯拉-godzilla-webshell-流量特征">6.6 哥斯拉（Godzilla）WebShell 流量特征</h3>
<p>哥斯拉是一款常见的 Java WebShell 管理工具，其流量特征可用于流量侧检测：</p>
<ul>
<li>初始化阶段产生一个较大的数据包（第一个），后续数据包较小；第一个响应体一般为空。</li>
<li>Cookie 末尾可能出现分号（有时没有）。</li>
<li>第二次请求携带 Cookie；响应体为 64 字节（前 16 + 中间 32 + 结尾 16）。</li>
<li>第三次及后续请求：前 16 与后 16 字节与第二次响应包一致（原因是 32 位 MD5 被拆成两部分，分别放在 base64 前后）。</li>
<li>关键参数：<code>xc</code>（加密密钥）、<code>pass</code>（解密密码）。</li>
<li>后门反连通道：TCP、HTTP、DNS、ICMP 等。</li>
</ul>
<p>常见 payload 句法特征：<code>[::-1]</code>（字符串反转）、<code>base64.b64decode(...)</code>、<code>zlib.decompress(...)</code>、<code>exec(...)</code>。</p>
<h3 id="6-7-webshell-流量分析详解">6.7 Webshell 流量分析详解</h3>
<blockquote>
<p>提示：若响应数据为 gzip 格式，注意提取位置，gzip 文件头为 <code>1F 8B 08 00</code>。</p>
</blockquote>
<h4 id="6-7-1-菜刀">6.7.1 菜刀</h4>
<p>特征：响应里可能有 <code>->| |&#x3C;-</code> 字符串。分析难度低，一般就是明文流量或 Base64 编码。</p>
<h4 id="6-7-2-哥斯拉">6.7.2 哥斯拉</h4>
<ul>
<li>默认密钥：<code>3c6e0b8a9c15224a</code></li>
<li>加密方式：通常为异或（插件加持下也可能用 AES）</li>

<h4 id="6-7-3-冰蝎">6.7.3 冰蝎</h4>
<ul>
<li>默认密钥：<code>e45e329feb5d925b</code>（<code>md5("rebeyond")</code> 的前 16 位）</li>
<li>加密方式：异或（与哥斯拉类似）或 AES（ECB/CBC）</li>
<li>找不到密钥时可先尝试默认密钥，或用 PuzzleSolver 爆破</li>

<p><strong>AES-CBC 解密（默认 PHP Webshell）：</strong></p>

<li>冰蝎 4.0 默认 IV 为 16 个 <code>\x00</code></li>
<li><code>openssl_decrypt($post, "AES128", $key)</code> 未传 IV，默认使用全 0 IV（AES-128-CBC）</li>
<li>自定义 IV 时需填入对应 IV（如 <code>0123456789abcdef</code>）</li>
</ul>

<h4 id="6-7-4-蚁剑">6.7.4 蚁剑</h4>
<p>蚁剑支持多种编码器（Reverse、ROT13、RSA 等），分析注意点：</p>
<ul>
<li>先判断攻击者用的编码器</li>
<li>路径 base64 字符串需<strong>去除前两个字符</strong>后再解码</li>
<li>响应数据头尾有额外字符，需先去除再 base64 解码</li>
</ul>

<h3 id="6-10-ntlm-认证流量分析">6.10 NTLM 认证流量分析</h3>
<p>NTLM 是 Windows 挑战/响应认证协议，消息嵌入在 SMB/HTTP/LDAP 等上层协议中，由三种消息构成：</p>
<table>
<thead>
<tr>
<th>类型</th>
<th>作用</th>
</tr>
</thead>
<tbody>
<tr>
<td>Type 1（协商）</td>
<td>客户端告知协议版本与功能</td>
</tr>
<tr>
<td>Type 2（质询）</td>
<td>服务器下发 8 字节 Challenge</td>
</tr>
<tr>
<td>Type 3（验证）</td>
<td>客户端返回用户名、域名与 Response</td>
</tr>
</tbody>
</table>
<p><strong>Net-NTLM Hash 格式：</strong></p>
<ul>
<li>Net-NTLMv1：<code>username::hostname:LM response:NTLM response:challenge</code>（已废弃，易破解）</li>
<li>Net-NTLMv2：<code>username::domain:challenge:HMAC-MD5:blob</code></li>
</ul>
<p><strong>NTLMv2 提取与爆破（SMB/HTTP）：</strong></p>
<ol>
<li>过滤 <code>ntlmssp</code>，在成功认证的包的 <code>Security Blob</code> 中复制 <code>User name</code>、<code>Domain name</code></li>
<li>从 <code>NTLMSSP_AUTH</code> 复制 <code>ntlmv2_response</code>（其开头即 <code>NTProofStr</code>）</li>
<li>从 <code>Session Setup Response</code> 复制 <code>NTLM Server Challenge</code></li>
<li>组合为：<code>username::domain:ServerChallenge:NTProofStr:ntlmv2_response</code></li>
</ol>
<pre><code class="hljs language-bash">hashcat -m 5600 hash.txt rockyou.txt
</code></pre>
<p>示例：</p>
<pre><code>administrator::WIN2008:9a88373dbb4f5e36:4eb74543b9962bb2ca36e938909bb930:0101000000000000...
</code></pre>
<blockquote>
<p>SMTP 中的 NTLM 信息可能 base64 编码，分析前需先解码。</p>
</blockquote>

<h3 id="6-11-kerberos-认证流量分析">6.11 Kerberos 认证流量分析</h3>
<p>Kerberos 是 MIT 提出的网络认证协议，通过 KDC（密钥分发中心）签发票据控制访问。三个角色：客户端、服务器、KDC。</p>
<p><strong>认证流程：</strong></p>
<ol>
<li><strong>AS Exchange</strong>：<code>AS-REQ</code>（客户端请求）→ <code>AS-REP</code>（KDC 返回 TGT）</li>
<li><strong>TGS Exchange</strong>：<code>TGS-REQ</code>（请求服务票据）→ <code>TGS-REP</code>（返回 Service Ticket）</li>
<li><strong>AP Exchange</strong>：<code>AP-REQ</code>（访问服务）→ <code>AP-REP</code>（权限验证）</li>
</ol>
<p><strong>PAC</strong>：微软扩展，在票据中嵌入用户 SID 与组信息，用 KDC 密钥与服务端哈希双重签名。</p>
<p><strong>解密 Kerberos 流量：</strong> 制作 keytab 文件并在 Wireshark <code>协议 → KRB5</code> 导入。Realm（域名）与 principal（主体名）从 <code>AS-REP</code> 获取（注意大小写），salt = Realm + principal。</p>
<pre><code class="hljs language-bash"><span class="hljs-comment"># 生成 keytab（需要 Realm、principal、密码）</span>
ktpass -princ &#x3C;principal> -pass &#x3C;password> -ptype KRB5_NT_PRINCIPAL -out keytab
</code></pre>

<h2 id="九-常见坑与避坑指南">九、常见坑与避坑指南</h2>
<h3 id="9-1-时间同步问题">9.1 时间同步问题</h3>
<p><strong>问题：</strong> 数据包时间戳与实际时间不一致</p>
<p><strong>解决方法：</strong></p>
<ul>
<li><code>View → Time Display Format</code> 切换到相对时间</li>
<li><code>Edit → Preferences → Protocols → IEEE 802.11</code> 检查时区设置</li>
<li>结合系统日志进行时间校准</li>
</ul>
<h3 id="9-2-加密流量处理">9.2 加密流量处理</h3>
<p><strong>问题：</strong> HTTPS流量无法直接读取内容</p>
<p><strong>解决方法：</strong></p>
<ul>
<li>寻找SSL密钥文件</li>
<li>检查是否有SSLKEYLOGFILE</li>
<li>在Wireshark中配置TLS解密</li>
<li>尝试查找未加密的通道</li>
</ul>
<h3 id="9-3-大数据量处理">9.3 大数据量处理</h3>
<p><strong>问题：</strong> PCAP文件过大，分析效率低</p>
<p><strong>解决方法：</strong></p>
<ul>
<li>使用显示过滤器缩小范围</li>
<li><code>File → Save As</code> 保存过滤后的数据包</li>
<li>使用 <code>editcap</code> 分割文件（命令行工具）</li>
<li>关注特定时间段或IP</li>
</ul>
<h3 id="9-4-协议混淆">9.4 协议混淆</h3>
<p><strong>问题：</strong> 攻击者使用非标准端口或协议伪装</p>
<p><strong>解决方法：</strong></p>
<ul>
<li>分析数据包特征而非依赖端口</li>
<li>使用 <code>Statistics → Protocol Hierarchy</code> 识别协议</li>
<li>关注应用层数据模式</li>
</ul>
<h3 id="9-5-usb设备地址识别">9.5 USB设备地址识别</h3>
<p><strong>问题：</strong> USB流量包含多个设备，难以区分</p>
<p><strong>解决方法：</strong></p>
<ul>
<li>使用 <code>usb.device_address</code> 字段过滤特定设备</li>
<li>查看 <code>usb.device_descriptor</code> 了解设备信息</li>
<li>通常键盘设备的 <code>usb.product</code> 包含 "Keyboard"</li>

<li>取消勾选不需要解析的协议</li>

<h3 id="10-4-profile管理">10.4 Profile管理</h3>

<ul>
<li>保存个性化的配置（过滤器、配色、列显示等）</li>

<li>设置协议解析选项</li>
</ul>
</li>
<li>
<p><strong>导出/导入Profile</strong></p>

</ul>
</li>
<li>

<li>选择目标Profile</li>
</ul>
</li>
</ol>
